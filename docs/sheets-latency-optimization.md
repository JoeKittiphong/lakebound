# ปรับความเร็ว Ranking — 28 ตุลาคม 2026

เผยแพร่ Apps Script version 2 โดยใช้ `/exec` URL และสิทธิ์เดิม

## สิ่งที่เปลี่ยน

- GET ที่มีแคชใช้ CacheService อ่านเพียงครั้งเดียว ไม่อ่าน PropertiesService, Sheets หรือรอ write lock
- แคช head อายุ 30 วินาที เปลี่ยนหลัง durable snapshot commit เท่านั้น และแยก namespace ของ QA จากของจริง
- POST ที่มีสถิติใหม่ข้าม read head เพื่อให้ผลหลังอัปโหลดไม่ย้อนกลับไปใช้แคชเก่า
- การ retry ที่เขียนสำเร็จแต่ refresh ติดล็อก จะทำ refresh ให้เสร็จก่อนตอบรับ ไม่ส่งอันดับเก่าแทน
- การสมัคร guest ที่ยังไม่มีคะแนนไม่ dirty/rebuild Ranking หรืออ่าน Scores โดยไม่จำเป็น
- เกมอ่านอันดับด้วย GET โดยไม่สมัคร guest เมื่อยังไม่มีสถิติใหม่ ชื่อและ token ส่งตอนมีสถิติจริงเท่านั้น
- บันทึกอันดับในเครื่องแบบ compact สูงสุด 7 ชุด × 100 แถว โหลดกลับหลังเปิดเกมใหม่ได้
- แสดงแคชทันทีพร้อมข้อความว่าเป็นข้อมูลที่บันทึกไว้ แล้วอัปเดตข้อมูลสดโดยไม่ปิดกั้นตัวเลือกแผนที่
- เปลี่ยนตัวกรองระหว่างโหลดได้ โดยยกเลิก request เก่า สถิติที่ยังไม่ตอบรับยังส่งซ้ำได้แบบ idempotent

| เงื่อนไข | ผล |
|---|---:|

| Burst อ่าน 100 คำขอ — สำเร็จ | 100/100 |

| Burst 100 — P95 | 4.375 s |

ข้อมูลสดแบบปกติและการแสดงแคชเข้าเป้าที่วัดได้ แต่ยังไม่ถึงเป้า 3 วินาทีสำหรับข้อมูลสดขณะยิง 100 คำขอพร้อมกัน
ยังไม่รับรอง SLA <3 s หรือ <1 s ในทุกสภาวะ การแสดงแคชอย่างรวดเร็วไม่ได้หมายความว่าข้อมูลสดมาถึงในเวลานั้น
การอัปโหลดสถิติ/เปลี่ยนชื่ออาจใช้เวลามากกว่า GET และยังไม่ได้ benchmark โหลดเขียนพร้อมกัน 100 คำขอ

ผล HTTP ปัจจุบันทดสอบกระดานว่าง ส่วนการวาด Top100 ใช้ข้อมูลจำลองในเครื่องเท่านั้น ไม่มีคะแนน QA บน Ranking จริง
ชุดทดสอบ burst รอบใหม่ใช้ TLS context ร่วมในเครื่องยิงโหลดเพื่อลดงานโหลด certificate store ซ้ำ แต่ยังตรวจใบรับรอง
และ hostname ตามปกติ จึงไม่ควรนำตัวเลขไปเทียบเป็นเปอร์เซ็นต์ตรง ๆ กับรายงานรุ่นแรกที่สร้าง TLS context ทุกคำขอ
ก่อน optimize รอบที่ยิงถี่ด้วย TLS context ร่วมพบ non-JSON 33/100 คำขอ; รอบหลัง optimize 100/100 สำเร็จ
ความแปรปรวนนี้ยังต้องคำนึงถึงเมื่อประเมินโหลดจริง ไม่ใช่การรับรองว่าทุก burst จะสำเร็จครบ
